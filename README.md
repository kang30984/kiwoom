# 시세 터미널

국내(키움증권)와 미국 주식 시세를 한 화면에서 보는 웹 애플리케이션입니다. 관심종목, 실시간 현재가, 호가 10단계, 월/주/일/분봉 차트, 거래량·등락률 순위, 그리고 변동성 기반 리스크 계산기를 제공합니다.

```
브라우저(React)  ──HTTP/WS──▶  내 서버(Node.js)  ──REST/WS──▶  키움 · 미국 시세 공급자
```

API 키는 서버에만 두고 브라우저는 이 서버만 바라봅니다. 브라우저에서 증권사 API를 직접 부르면 CORS에 막히고 시크릿키가 노출됩니다.

## 바로 실행

**API 키 없이 돌아갑니다.** 처음 실행하면 가짜 시세(데모 모드)로 시작하므로 계좌나 키 발급 없이 전체 기능을 확인할 수 있습니다.

```bash
git clone <https://github.com/kang30984/kiwoom>
cp .env.example server/.env

cd server \&\& npm install \&\& npm start   # 터미널 1
cd web    \&\& npm install \&\& npm run dev # 터미널 2
```

Windows 는 `start.bat` 더블클릭, macOS/Linux 는 `bash start.sh` 로 위 과정을 한 번에 처리합니다. 처음 실행하는 사람에게는 [**START-HERE.md**](START-HERE.md) 를 안내하세요.

**요구사항** — Node.js 20 이상 (`.nvmrc` 참고)

## ⚠️ 면책 조항

* **이 프로그램은 투자 조언을 제공하지 않습니다.** 매수·매도 방향을 제시하는 기능은 의도적으로 넣지 않았습니다.
* 매매계획의 손절가·익절가·수량은 **과거 변동성(ATR)에서 기계적으로 계산한 값**이며 가격 예측이 아닙니다. 해당 가격에 도달한다는 보장이 없습니다.
* **데모 모드의 숫자는 실제 시세가 아닙니다.** 프로그램이 생성한 가짜 값입니다.
* 계산된 최대 손실은 상한이 아닙니다. **갭 하락 시 손절가보다 낮은 가격에 체결됩니다.**
* 거래비용·세율 기본값은 가정값입니다. 본인 계좌 조건으로 바꿔 쓰세요.
* 투자 판단과 그 결과는 사용자 본인의 책임입니다.

## 보안

* **`.env` 를 절대 커밋하지 마세요.** `.gitignore` 에 포함되어 있습니다. 여기에 키움 앱키·시크릿키와 미국 시세 API 키가 들어갑니다.
* 실수로 커밋했다면 즉시 **키를 재발급**하세요. 커밋 이력에서 파일만 지워도 이미 노출된 키는 유효합니다.
* 다른 사람에게 본인의 키를 주지 마세요. 호출 한도와 계좌 권한을 공유하게 됩니다.
* 이 프로그램은 **시세 조회만** 하며 주문 기능이 없습니다.

## 실행하기

Node.js LTS만 설치돼 있으면 됩니다 ([nodejs.org](https://nodejs.org)).

**Windows** — `start.bat` 더블클릭
**macOS / Linux** — 터미널에서 폴더로 이동한 뒤 `bash start.sh`

스크립트가 `.env` 생성 → 패키지 설치 → 백엔드 기동 → 브라우저 새 창 오픈까지 알아서 합니다. 첫 실행은 패키지 설치 때문에 1\~2분 걸리고, 이후에는 몇 초입니다.

수동으로 하려면 터미널 두 개를 씁니다:

```bash
cp .env.example server/.env
cd server \&\& npm install \&\& npm start     # 터미널 1
cd web \&\& npm install \&\& npm run dev      # 터미널 2
```

`http://localhost:5173`

### 데모 모드 (기본값)

앱키가 없어도 화면이 돕니다. `.env` 의 `DEMO=true` 상태에서는 키움에 접속하지 않고 서버가 가짜 시세를 만들어 흘려보냅니다. 랜덤워크로 가격이 움직이니 실시간 점멸, 호가창, 차트, 순위가 전부 동작하는 걸 볼 수 있습니다. **당연히 실제 시세가 아닙니다.**

우측 상단 표시등이 빨갛게 켜져 있으면 실시간 스트림이 붙은 상태입니다.

### 실제 시세로 바꾸기

1. 키움증권 로그인 → 오픈API 신청 → 앱키·시크릿키 발급
2. `server/.env` 수정:

```
   DEMO=false
   KIWOOM\_APP\_KEY=발급받은\_앱키
   KIWOOM\_SECRET\_KEY=발급받은\_시크릿키
   KIWOOM\_MOCK=true     # 모의투자로 먼저 확인하는 편이 안전합니다
   ```

3. 백엔드 재시작

`server/.env` 는 `.gitignore` 에 들어 있습니다. 커밋에 시크릿키가 섞이지 않게 그대로 두세요.

## 매매계획 패널 (우측 "매매계획" 탭)

**이 기능은 매수/매도 방향을 제시하지 않습니다.** 어떤 종목을 사야 하는지, 오를지 내릴지 판단하는 기능은 의도적으로 넣지 않았습니다. 진입 결정은 사용자가 하고, 여기서는 그 결정에 딸린 숫자만 계산합니다.

입력은 세 가지입니다.

|입력|의미|
|-|-|
|투자 가능 자금|이 종목에 배정할 총액이 아니라, 리스크 계산의 기준이 되는 전체 자금|
|감당할 손실 %|그 자금 중 이 한 번의 매매로 잃어도 되는 비율. 1\~2%가 통상적인 범위입니다|
|ATR 배수|손절폭을 일평균 변동폭의 몇 배로 둘지 (기본 2)|

계산 흐름:

```
ATR(14)  ─×배수─→  손절폭  ─────→  손절가
                     │
                     ├─×1,2,3──→  익절가 1R / 2R / 3R
                     │
                     └─ 감당손실 ÷ 손절폭 ──→ 수량 ──→ 투입금액, 최대손실
```

**손절폭을 고정 비율(5% 등)이 아니라 ATR로 잡는 이유.** 하루에 1% 움직이는 종목과 6% 움직이는 종목에 같은 손절폭을 쓰면, 전자는 손절이 너무 멀어 손실이 커지고 후자는 정상적인 일중 변동에 튕겨 나갑니다. ATR 배수는 종목의 실제 변동폭에 손절폭을 맞춥니다.

**1R = 손절폭 1배.** 손절가까지 거리가 2,000원이면 1R 익절은 +2,000원입니다. 손익비를 가격이 아니라 배수로 보는 이유는, 승률과 묶어 계산할 수 있기 때문입니다. 2R 목표라면 승률 34%만 넘어도 기대값이 양수입니다.

### 평균단가와 보유 수량은 독립적입니다

각각 따로 쓸모가 있습니다.

|입력|계산되는 것|
|-|-|
|보유 수량만|평가 금액, 손절되면 얼마를 잃는지|
|평균단가만|현재 손익률, 원금 회복가|
|둘 다|위 전부 + 평가손익|

예전에는 `if (avgCost)` 가 전체를 감싸서 **평균단가가 없으면 보유 수량을 통째로 버렸습니다.** 입력해도 화면에 아무 변화가 없어 무시된 줄도 모르는 상태였습니다. 지금은 있는 것만으로 계산하고, 빠진 입력이 무엇인지 알려줍니다.

### 큰 숫자 읽기

합계 금액과 수량은 **한국식 단위(만·억·조·경)로 줄여서** 보여줍니다. `9,999,999,999,904,000원` 을 그대로 두면 자릿수를 세야 하고, 화면에서는 아무 의미도 전달되지 않습니다.

```
      829,000,000원  ->  8.3억원
3,873,831,775,484,000원  ->  3,874조원
        6,031,363,088주  ->  60.3억주
```

**가격은 줄이지 않습니다.** 손절가·익절가·현재가는 정확한 값이어야 하고, 금액과 섞으면 헷갈립니다. 줄인 표시에 마우스를 올리면 정확한 값이 `title` 로 나옵니다.

미국 탭은 `$1.5M` / `$2.3B` 처럼 영어 단위를 씁니다.

### 보유 손실 비율의 분모

`손절 시 손실` 의 비율은 **평가금액** 기준입니다. 자금 대비로 하면 자금이 크게 입력됐을 때 `0.0%` 가 되어 아무 정보도 주지 않습니다. 평가금액 대비로 하면 손절폭 % 와 정확히 일치해서 검산도 됩니다 (평가액의 25.81% = 손절폭 25.81%).

### 보유분은 예산 대비로 본다

보유 수량의 `손절 시 손실` 을 **평가액 대비 %** 로 보여주면 손절폭 % 와 수학적으로 같은 값이 나옵니다 (수량이 약분됨). 같은 정보를 두 번 보여주는 셈입니다.

대신 **감당 손실 예산 대비**로 보여줍니다. 자금 1,000만 원 · 감당 손실 2%인 사람이 167만 원짜리 종목 500주를 들고 있으면 손절 시 예산의 **535배**를 잃습니다 — 이미 보유한 수량이 정한 리스크 허용치를 한참 넘었다는 뜻이고, 이건 바로 행동으로 이어지는 정보입니다. 100%를 넘으면 경고도 함께 띄웁니다.

비율은 `<0.1%` · `535%` · `535배` 처럼 크기에 따라 표기를 바꿉니다. 고정 소수점을 쓰면 아주 작은 값이 `0.0%` 로 뭉개져 의미를 잃습니다.

### 유동성 점검

권장 수량이 최근 20일 평균 거래량의 5%를 넘으면 경고합니다. 투자금을 잘못 입력하면 4,300만 주 같은 값이 나오는데, 시장이 소화할 수 없는 규모라 계산상의 숫자일 뿐입니다.

### 수량은 두 기준을 함께 보여줍니다

`살 수 있는 수량` 하나만 보여주면 오해를 부릅니다. 두 기준은 서로 다른 질문에 답합니다.

|기준|질문|산식|
|-|-|-|
|자금 전액|돈으로 몇 주까지 살 수 있나|투자금 ÷ 현재가|
|감당 손실|손절되면 정한 금액만 잃으려면 몇 주까지|(투자금 × 손실%) ÷ 주당 손절폭|

**권장 수량은 둘 중 작은 값**입니다. 자금이 없으면 살 수 없고, 리스크 한도를 넘기면 애초에 정한 손실 상한이 무의미해집니다. 어느 쪽이 수량을 묶는지 표에서 강조 표시하고, 자금을 다 썼을 때의 손실도 나란히 보여줍니다.

예: 현재가 167.5만 원, ATR 12.7%, 자금 1,000만 원, 감당 손실 10%

```
자금 전액     5주   투입 837.5만   손절 시 -213.5만 (자금의 21.3%)
감당 손실 10% 2주   투입 335.0만   손절 시  -85.4만 (자금의  8.5%)
→ 권장 2주
```

리스크 기준이 자금을 넘을 때도 자금으로 자릅니다. 저변동 종목에서 리스크 기준 555주가 나오지만 자금으로는 135주뿐이면 **135주**입니다. 예전에는 555주를 그대로 표시하고 경고만 띄워, 실행할 수 없는 숫자를 권장하는 문제가 있었습니다.

**목표가보다 수량이 중요합니다.** 목표가는 도달 여부를 아무도 모르지만, 수량은 손실 상한을 확정합니다. 계산된 수량으로 진입하면 손절에 걸려도 잃는 금액이 입력한 범위를 넘지 않습니다.

**손익분기가.** 매수 수수료를 물고 들어가 매도 수수료·세금을 떼고 나올 때 원금이 되는 가격입니다. 이 위로 올라가야 비로소 수익입니다.

**경고 문구의 통화 표기는 시장 객체가 제공합니다.** `markets.js` 의 `money()` / `price()` 를 `computePlan` 이 받아 씁니다. 문구에 `원` 을 하드코딩하면 미국 탭에서 달러 금액을 원이라고 말하게 됩니다. 한국어 조사(`이/가`)는 통화 표기의 끝음에 따라 달라지므로, 금액 뒤에 조사가 붙지 않는 문장으로 씁니다.

`krx.js` 의 `DEFAULT\_COSTS` 수수료·세율은 **가정값입니다.** 증권사 수수료는 계좌·이벤트별로 크게 다르고 증권거래세율은 개정이 잦으니, 본인 계좌 조건으로 바꿔 쓰세요.

가격은 전부 KRX 호가단위에 맞춰 스냅됩니다 (손절은 내림, 익절은 올림).

**일일 가격제한폭으로 자르지 않습니다.** ±30%는 당일 제한이고 익절 목표는 며칠에 걸쳐 도달하는 값입니다. 오늘 상한가로 자르면 배수를 바꿔도 목표가가 전부 같은 값으로 뭉쳐 계산기가 무용지물이 됩니다. 대신 `당일 도달 불가` 로 표시하고 오늘의 상·하한가를 참고로 함께 보여줍니다.

손절가도 하한가로 끌어올리지 않습니다. 그렇게 하면 손절폭이 줄어 **수량이 과대 계산되고 실제 위험이 과소평가됩니다** — 리스크 계산기에서 가장 위험한 종류의 오류입니다.

### 이 계산이 못 하는 것

* 가격 예측을 하지 않습니다. ATR은 과거 변동폭이고 미래를 보장하지 않습니다.
* 갭 하락을 막지 못합니다. 손절가를 70,300원으로 잡아도 다음날 68,000원에 시작하면 그 가격에 체결됩니다. 계산된 최대손실은 하한선이 아닙니다.
* 재무·실적·뉴스를 보지 않습니다. 순수하게 가격 변동폭만 씁니다.
* 분할 매수·매도, 세금 상세, 신용·미수는 반영하지 않습니다.

### 차트 조회 기간

첫 화면은 **일봉 1년**이 기본입니다. `config.js` 의 `CHART\_YEARS` 에서 봉 종류별로 조정합니다 (일봉 1년 · 주봉 3년 · 월봉 6년). 탭을 옮길수록 더 긴 흐름을 보게 되는 구성입니다. 요청 시 `?years=3` 으로 덮어쓸 수 있습니다.

키움은 한 번에 주는 행 수가 제한적이라, 긴 기간을 채우려면 `cont-yn` 페이징으로 이어 받아야 합니다. `fetchCandles` 는 **목표 시작일까지 확보하면 즉시 중단**하므로 필요 이상으로 호출하지 않습니다 (최대 10페이지).

매매계획은 같은 함수를 쓰지만 일봉을 짧게(120봉) 받습니다. ATR(14)과 최근 20일 스윙에만 쓰이므로 3년치를 받아도 결과가 같고 호출만 늘어납니다.

### 차트 상태 초기화

새 데이터를 요청하기 전에 **기존 캔들을 반드시 비웁니다** (`setData(\[])`). 이걸 빼면 요청이 느리거나 실패했을 때 이전 종목·시장의 캔들이 그대로 남습니다. 국내 7만원대와 미국 140달러대는 가격대가 전혀 달라, 남아 있으면 다른 종목 차트를 보고 있다는 걸 알아채기 어렵습니다.

봉 개수를 헤더에 표시(`차트 · 261봉`)하는 것도 같은 이유입니다. 데이터가 짧게 왔는지 눈으로 바로 확인할 수 있습니다.

### 봉 종류 추가하기

년봉 등을 붙이려면 두 곳만 고치면 됩니다.

1. `server/src/config.js` 의 `TR` 에 api-id 추가 → `routes/chart.js` 의 `CHART\_TR` 에 매핑 추가
2. `web/src/components/PriceChart.jsx` 의 `PERIODS` 배열에 `\['year', '년봉']` 추가

유효한 타입 목록은 `CHART\_TR` 의 키에서 자동으로 파생되므로 검증 코드를 따로 손댈 필요는 없습니다. 데모 모드에서도 보이게 하려면 `demoFeed.js` 의 `count`·`shockScale`·`wickScale` 표에 항목을 추가하세요.

### 종목명 검색

입력할 때마다 키움 API를 부르면 호출 한도에 걸립니다. 그래서 `ka10099`로 **코스피·코스닥 종목 마스터를 한 번 받아 서버 메모리에 12시간 캐시**하고, 검색은 그 안에서 처리합니다. 브라우저는 `/api/search?q=삼성` 만 부르면 됩니다.

검색은 **2단계**입니다. 글자를 넣으면 그 글자를 포함하는 종목이 아래에 뜨고, 하나를 고르면 검색란에 종목명이 채워집니다. 그 상태에서 `추가` 를 누르면 관심종목에 들어갑니다. 고르자마자 추가되지 않으니 종목을 확인한 뒤 결정할 수 있습니다.

고른 직후에는 그 종목명으로 재검색하지 않습니다. 이게 없으면 검색란이 채워지는 순간 드롭다운이 다시 열립니다.

이때 **boolean 플래그를 쓰면 안 됩니다.** 이미 `삼성전자` 를 다 입력한 상태에서 목록의 `삼성전자` 를 고르면 `setQuery` 가 같은 값이어서 effect 가 돌지 않고, 플래그가 `true` 로 남아 **다음 키 입력을 삼켜버립니다.** `skipQuery` 에 건너뛸 검색어 자체를 담고, 사용자가 직접 입력하면 무조건 지웁니다.

목록에서 고른 뒤 드롭다운을 닫을 때 `setOpen(false)` 하나로는 부족합니다. `select()` 가 입력란에 다시 focus 를 주는데, 그 `onFocus` 핸들러가 **아직 갱신되지 않은 `items`** 를 보고 `setOpen(true)` 로 되돌려 놓습니다. 같은 배치 안에서 나중에 실행되므로 그쪽이 이깁니다. 결과적으로 드롭다운은 열린 채 `items` 만 비어, `'삼성전자' 을 포함하는 종목이 없습니다` 라는 엉뚱한 안내가 뜹니다.

그래서 렌더 조건 자체에 `!picked` 를 넣어 최종 차단하고, `onFocus` 에도 같은 조건을 걸었습니다. 그리고 `'없습니다'` 는 **현재 검색어로 검색이 실제로 끝났을 때만**(`searchedFor === query`) 말하도록 했습니다.

검색 드롭다운은 절대배치이므로 **상단 패널에 `overflow: auto` 를 걸면 안 됩니다.** z-index 와 무관하게 패널 경계에서 잘려나갑니다. `.pane--top` 만 `overflow: visible` 로 두고 `z-index` 를 올렸습니다. 검색창도 상단바 왼쪽에 두어, 드롭다운이 호가창이 아니라 차트 영역 위로 펼쳐지게 했습니다.

일치하는 종목이 없는 상태에서 `추가` 를 누르면 알림이 뜹니다. 드롭다운을 닫고 그 자리에 표시하므로 두 메시지가 겹치지 않습니다.

정렬 우선순위는 코드 완전일치 → 이름 완전일치 → 이름 앞부분 → 코드 앞부분 → 이름 포함입니다. 같은 순위면 이름이 짧은 쪽을 위로 올립니다 — `삼성전자` 가 `삼성전자우` 나 레버리지 ETF보다 먼저 나와야 하기 때문입니다.

마스터를 못 받았을 때(`ka10099` 불일치 등)와 단순히 검색 결과가 없을 때를 구분해서 안내합니다. 전자는 6자리 코드 입력으로 우회할 수 있고, 이 경로는 마스터와 무관하게 항상 동작합니다.

## 미국 증시 탭

상단 `국내 / 미국` 탭으로 전환합니다. 관심종목·차트·매매계획은 두 시장이 각각 따로 저장됩니다.

### 왜 별도 탭인가

**시장 규칙이 정반대인 항목이 많습니다.**

|항목|국내|미국|
|-|-|-|
|상승 색|빨강|**초록**|
|호가단위|가격대별 1\~1,000원|$0.01 (1달러 미만 $0.0001)|
|일일 가격제한폭|±30%|없음|
|종목코드|6자리|티커 (`AAPL`, `BRK.B`)|
|호가창|10단계 제공|무료 API 미제공|
|시세|실시간 WebSocket|15분 지연 REST|

특히 **색 관례가 반대**인 게 위험합니다. 한 화면에 섞으면 빨강을 어느 쪽에서는 상승, 어느 쪽에서는 하락으로 읽습니다. `.shell\[data-market='US']` 에서 `--up` / `--down` 변수만 뒤집으면 `.up` / `.down` 클래스를 쓰는 모든 곳이 따라옵니다.

시장 규칙은 `markets.js` 에 모아 두고 `computePlan` 에 주입합니다. 그래서 같은 계산기가 두 시장에서 각자 맞는 호가단위·제한폭·수수료로 동작합니다. 미국은 가격제한폭이 없으니 `당일 도달 불가` 표시도 나오지 않고, 수수료가 0이니 손익분기 줄도 숨겨집니다.

### 시세 공급자

무료 API의 한도와 정책은 자주 바뀌므로 `us/provider.js` 어댑터로 분리했습니다. 세 함수만 같은 모양으로 구현하면 어떤 공급자든 붙습니다.

```
search(query)              -> \[{ code, name, exchange }]
quote(symbol)              -> { code, name, price, change, changeRate, ... }
candles(symbol, type, n)   -> \[{ time, open, high, low, close, volume }]
```

`.env` 에서 선택합니다.

```
US\_PROVIDER=demo          # 키 없이 가짜 데이터
US\_PROVIDER=twelvedata    # https://twelvedata.com 무료 가입 (15분 지연)
US\_API\_KEY=발급받은\_키
```

### 잘린 이름 툴팁

종목명이 `...` 으로 잘린 경우 마우스를 올리면 전체가 뜹니다 (`Truncated` 컴포넌트).

**툴팁을 `position: fixed` 로 띄웁니다.** 관심종목 패널과 검색 드롭다운은 `overflow: auto` 라서 안쪽에 절대배치하면 경계에서 잘립니다 — 검색 드롭다운이 잘렸던 것과 같은 원인입니다.

`scrollWidth > clientWidth` 로 **실제로 잘렸을 때만** 표시합니다. 짧은 이름에까지 뜨면 같은 내용을 두 번 보여주는 셈입니다. 화면 오른쪽 끝에서는 안으로 당겨오고, 스크롤·리사이즈 중에는 좌표가 어긋나므로 닫습니다. 키보드 포커스로도 동작하고, 터치 환경 대비로 `title` 속성도 함께 둡니다.

### 캔들 정렬

`lightweight-charts` 는 시간이 **엄격히 증가하고 중복이 없어야** 정상 동작합니다. 어긋나면 시간축 라벨이 `9월 10월 4월 12월` 처럼 뒤엉켜 표시됩니다.

페이징으로 여러 번 받아 이어 붙이면 두 가지가 깨질 수 있습니다 — 페이지가 겹쳐 같은 날짜가 두 번 들어오거나, '다음 페이지는 항상 더 과거' 라는 가정이 틀리는 경우입니다. 그래서 병합 후 `normalizeCandles()` 로 한 번 정렬·중복 제거합니다. 국내와 미국 경로 모두 같은 처리를 거칩니다.

### 차트를 비우는 시점

종목이나 시장이 바뀌면 **새 데이터를 받기 전에 먼저 캔들을 비웁니다.** 받아온 결과로 덮어쓰기만 하면, 그 요청이 실패하거나 느릴 때 이전 종목의 차트가 그대로 남습니다. 미국 탭에서 국내로 전환했을 때 미국 캔들이 계속 보이는 증상이 이것이었습니다.

### 없는 종목 다루기

**추가 버튼을 누르면 시세를 실제로 조회해서 값이 오는지 확인한 뒤 목록에 넣습니다.**

이때 흐름을 하나로 묶어야 합니다. 검색으로 존재를 보는 흐름과 시세로 확인하는 흐름이 따로 돌면, 확인이 호출 한도 큐에 걸린 동안 검색 쪽이 먼저 "없습니다" 알림을 띄워 **알림과 `확인 중…` 버튼이 동시에 보이는 모순**이 생깁니다. `addCode` 가 성공 여부를 돌려주고 `submit()` 이 그것을 기다립니다. 실패하면 입력을 비우지 않아 사용자가 무엇을 시도했는지 볼 수 있습니다.

**검색이 호출 한도(429)나 타임아웃(408)으로 실패했다면 시세 확인 단계로 넘어가지 않습니다.** 같은 큐에 막혀 있으니 10초를 더 기다리게 할 이유가 없습니다. 바로 `호출 한도 대기 중입니다` 로 알립니다. 그 외의 실패는 판단 근거가 없으므로 확인 단계로 넘겨 시세로 걸러냅니다.

안내 문구는 모두 시장별로 갈라집니다. 미국 탭에서 `6자리 코드로 입력해 주세요` 처럼 국내 규칙을 말하면 안 됩니다.

확인용 조회는 **10초**로 끊습니다 (일반 조회는 25초). 사용자가 버튼 앞에서 기다리는 요청이라 오래 잡고 있을 수 없습니다. 겹친 확인 요청은 토큰으로 마지막 것만 반영합니다. 검색 결과만 믿으면, 검색 색인에는 있지만 시세가 없는 종목이 통과합니다. 이 확인 조회는 캐시되므로 곧이어 실행되는 스냅샷 조회가 재사용하고, 호출 수는 늘지 않습니다.

**보고 있는 종목을 삭제하면 선택도 함께 옮깁니다.** 이걸 빠뜨리면 목록에서 사라진 종목의 시세를 계속 조회하며 헤더에 남아, 삭제했는데도 화면에 그대로 있는 것처럼 보입니다.



미국 탭에서 티커를 직접 입력할 때, **검색이 성공했는데 0건이면 추가를 막습니다.** 검색 색인이 상장 여부의 근거이기 때문입니다. 검색 자체가 실패한 경우에는 판단 근거가 없으니 통과시킵니다.

**판정 전에 검색이 끝났음을 보장해야 합니다.** `searchedFor` 같은 상태만 보고 판단하면, 빠르게 입력하고 곧바로 `추가` 를 누를 때 디바운스가 끝나기 전이어서 '검색 안 해봤음' 으로 오판되고 그대로 통과합니다. `submit()` 이 필요하면 직접 검색을 await 한 뒤 판정합니다.

그리고 알림을 띄운 뒤 **뒤늦게 끝난 디바운스 검색이 드롭다운을 다시 열어 알림을 가리지 않도록** `noticeFor` 로 막습니다. 없는 종목 문구는 `notFoundText()` 한 곳에서 만들어 드롭다운과 알림이 같은 말을 합니다.

이미 관심종목에 들어간 종목이 빈 시세를 돌려주면 `갱신 중` 으로 방치하지 않고 원인을 안내하고 삭제 버튼을 띄웁니다. **응답이 8초를 넘겨도** 같은 안내와 삭제 경로를 엽니다 — 호출 한도 큐에 걸려 응답이 없으면 안내 조건(`!quoteLoading`)이 성립하지 않아 사용자가 갇힙니다. 비상장 기업(예: SpaceX)은 어떤 거래소에도 티커가 없어 시세가 존재하지 않습니다.

모든 요청에 **25초 타임아웃**을 걸었습니다. 호출 한도 큐 때문에 오래 걸릴 수는 있지만 무한정 기다리면 원인을 알 수 없습니다.

### 호출 한도

무료 티어는 분당 호출 수가 아주 적습니다 (Twelve Data 기본 **8회/분**). 화면 한 번 열 때 관심종목 + 차트 + 계획을 몰아서 부르므로 아무 장치가 없으면 곧바로 한도 초과가 납니다. `us/gate.js` 가 세 가지로 막습니다.

1. **캐시** — 시세 1분 · 캔들 10분 · 검색 1시간. 15분 지연 데이터를 매번 다시 받을 이유가 없습니다
2. **중복 제거** — 같은 키로 동시에 들어온 요청은 하나만 실제로 보냅니다 (관심종목 시세와 선택 종목 시세가 겹칩니다)
3. **토큰 버킷** — 한도를 넘으면 오류 대신 잠시 기다린 뒤 보냅니다
4. **stale-while-revalidate** — 캐시가 만료됐어도 너무 낡지 않았으면 기다리지 않고 그 값을 주고, 갱신은 뒤에서 진행합니다. 15분 지연 데이터라 2분 전 값이 빈 화면보다 낫습니다

그리고 화면 쪽에서도 대비합니다. 종목 헤더는 **실시간 > 방금 받은 스냅샷 > 관심종목에 이미 있는 값** 순으로 표시합니다. 마지막 대안이 없으면 호출 한도 큐에 걸린 동안 헤더가 통째로 비어 보입니다 — 관심종목에는 가격이 있는데도요. 갱신 중일 때는 종목명 옆에 `갱신 중…` 이 뜹니다.

차트와 매매계획이 **같은 크기의 일봉(261봉)을 요청**하도록 맞춰 캐시를 공유합니다. 크기가 다르면 캐시 키가 갈려 호출이 두 배가 됩니다.

그 결과 관심종목 4개 + 차트 1개인 화면은 **5회**로 끝나고, `계산하기` 를 눌러도 캐시를 재사용해 늘지 않습니다.

한도가 다른 요금제라면 `.env` 의 `US\_RATE\_PER\_MIN` 을 고치세요.

**twelvedata 어댑터는 실제 API로 검증하지 못했습니다** (이 환경에서 해당 도메인에 접근할 수 없습니다). 필드명이 어긋나면 `us/provider.js` 의 `quote()` / `candles()` 파싱부만 고치면 됩니다. Finnhub·Alpha Vantage·Polygon 등도 같은 자리에 추가할 수 있습니다.

### 미국 탭에 없는 것

* **호가창** — 무료 시세 API는 depth 를 주지 않습니다
* **거래량·등락률 순위** — 키움 순위 TR 은 국내 전용입니다
* **분봉** — 무료 티어는 대개 일봉 이상만 제공합니다
* **실시간** — 15분 지연입니다. 상단에 표시됩니다

### 세금 주의

미국 주식은 **양도소득세**(연 250만원 공제 후 22%) 대상이고 연말 정산 방식이라, 국내처럼 건별 손익분기에 반영할 수 없습니다. 그래서 미국 탭의 기본 거래비용은 0이고 손익분기 줄이 표시되지 않습니다. 환율 변동도 반영하지 않습니다 — 수량 계산은 달러 기준입니다.

## 설계 결정 몇 가지

**실시간 연결은 하나만.** 키움은 연결당 등록 종목 수에 제한이 있어서, 서버가 업스트림 1개만 열고 브라우저들에게 팬아웃합니다. 종목별 구독자 수를 세서 **아무도 보지 않는 종목만 REMOVE**를 보냅니다. 탭을 여러 개 열어도 키움 쪽 등록은 늘어나지 않습니다.

**PING은 반드시 되돌려 보내야 합니다.** 키움이 보내는 `{"trnm":"PING"}`을 그대로 echo하지 않으면 연결이 끊깁니다.

**응답 파싱을 느슨하게.** TR마다 배열이 담긴 키 이름이 다르고(`stk\_dt\_pole\_chart\_qry` 등) 문서 개정으로 바뀌기도 합니다. `firstArray()`는 응답에서 첫 배열을 찾아 쓰고, 호가는 `sel\_3th\_pre\_bid` 같은 키를 정규식으로 훑습니다. 필드명이 어긋나도 전체가 죽지 않습니다.

**종목코드 정규화.** 키움은 거래소 구분 접미사를 붙여 줍니다 — `233740\_AL`(통합) · `005930\_NX`(넥스트레이드) · `005930\_KR`(한국거래소). 넥스트레이드 출범 이후 생긴 형식입니다. 이걸 그대로 시세 조회에 쓰면 빈 값이 돌아옵니다. `normalizeCode()` 가 접미사를 떼고 6자리만 남기며, 순위·마스터 응답과 라우트로 들어오는 코드 양쪽에 적용합니다. 프론트엔드도 같은 규칙을 갖고 있어서, 예전 버전이 저장해 둔 잘못된 코드를 불러올 때 씻어냅니다.

**숫자 정규화.** 키움은 `"+1,200"`, `"-500"` 처럼 부호와 콤마가 섞인 문자열을 줍니다. 가격·잔량은 절댓값으로, 전일대비·등락률은 부호를 살려서 처리합니다.

## 확인이 필요한 부분

`config.js`의 **api-id와 `realtime.js`의 FID 번호는 반드시 공식 문서와 대조**하세요. 키움은 TR 코드와 필드명을 개정하는 편이고, 잘못된 api-id는 `return\_code != 0`으로 조용히 실패합니다. 서버 로그에 `키움 API가 실패를 반환했습니다`가 뜨면 대개 이 문제입니다.

디버깅할 때는 `NODE\_ENV=development`로 서버를 띄우면 `/api/quote/:code` 응답에 키움 원본 `raw`가 함께 담겨서, 실제 필드명을 바로 확인할 수 있습니다.

## 화면 규칙

* **상승은 빨강, 하락은 파랑** — 한국 시장 관례입니다. 서양식 초록/빨강과 반대이므로 색을 바꾸면 오독을 부릅니다.
* 색은 등락 방향에만 씁니다. 나머지 UI는 전부 무채색이라 화면에 빨강이 보이면 무조건 "오른 것"입니다.
* 모든 숫자는 등폭 서체 + `tabular-nums`로 자릿수가 세로로 맞습니다.
* 체결이 들어오면 해당 행이 400ms 점멸합니다. `prefers-reduced-motion`을 켠 사용자에게는 생략됩니다.
